### H6 — Migration: migrate Google provider data + drop columns

File: `priv/repo/migrations/YYYYMMDDHHMMSS_migrate_google_identities_and_drop_columns.exs`

This migration has two parts:

1. **Data migration**: Copy `google_provider_id` from `users` into
   `user_identities` so existing Google-linked accounts continue working
   under ash_authentication's `UserIdentity` model.
2. **Schema cleanup**: Drop the dead columns.

```elixir
defmodule Firmowid.Repo.Migrations.MigrateGoogleIdentitiesAndDropColumns do
  use Ecto.Migration

  def up do
    # 1. Copy existing Google links into user_identities.
    #    The UserIdentity resource expects: user_id, uid (provider's user ID),
    #    strategy (strategy name atom as string), and provider (provider name).
    #    Only insert for users that have a google_provider_id and don't already
    #    have a matching identity (idempotent).
    execute """
    INSERT INTO user_identities (id, user_id, uid, strategy, provider, inserted_at, updated_at)
    SELECT
      gen_random_uuid(),
      u.id,
      u.google_provider_id,
      'google',
      'google',
      NOW(),
      NOW()
    FROM users u
    WHERE u.google_provider_id IS NOT NULL
      AND NOT EXISTS (
        SELECT 1 FROM user_identities ui
        WHERE ui.user_id = u.id AND ui.strategy = 'google'
      )
    """

    # 2. Drop the columns
    alter table(:users) do
      remove :google_provider_id
      remove :provider
      remove :provider_id
    end
  end

  def down do
    alter table(:users) do
      add :google_provider_id, :string
      add :provider, :string, default: "password"
      add :provider_id, :string
    end

    # Restore google_provider_id from user_identities
    execute """
    UPDATE users u
    SET google_provider_id = ui.uid
    FROM user_identities ui
    WHERE ui.user_id = u.id AND ui.strategy = 'google'
    """
  end
end
```

**Important:** Check the exact column names on `user_identities` — they depend
on how the `AshAuthentication.UserIdentity` resource defines its attributes.
Verify against `lib/firmowid/ash/core/user_identity.ex` and the sub-phase B
migration that created the table. The key fields are likely `uid`, `strategy`,
`provider`, and `user_id`.
