# Phase E — Code interfaces + resource prep

## Goal

Add code interfaces to `Firmowid.Ash.Core` so every public operation on User,
Organization, and OrganizationInvite is callable via the domain module. Add
`AshPhoenix` extension for form helpers. Add `remember_me` strategy to User.

## Decisions

- Domain module (`core.ex`) is the only public API — callers never touch
  resources directly.
- `extensions: [AshPhoenix]` on the domain generates `form_to_*` helpers
  alongside code interfaces.
- Avatar loading is NOT a code interface — callers use
  `Ash.load!(entity, [avatar_blob: [:url]], tenant: ..., authorize?: false, actor: %{})`
  at callsites.
- `remember_me` strategy added now to avoid a second pass during auth rewrite.
- Cost ceiling (`seconds_to_hours`) stays on Timetracker domain — it's a
  business rule, not a view concern.

## Steps

### E1 — Add AshPhoenix extension to Core domain

File: `lib/firmowid/ash/core/core.ex`

```elixir
use Ash.Domain, extensions: [AshPhoenix]
```

This enables `Core.form_to_<action_name>()` helpers for all defined code
interfaces.

### E5 — Add User `:list` read action

File: `lib/firmowid/ash/core/user.ex`

Add a flexible read action following the Transaction pattern (optional filter
arguments with `prepare build(filter:) where present(:arg)`):

```elixir
read :list do
  argument :search, :string

  prepare build(
    filter: expr(
      contains(name, ^arg(:search)) or contains(email, ^arg(:search))
    )
  ) do
    where present(:search)
  end
end
```

**Note:** Check if `contains` (case-insensitive) works in Ash expressions or if
`fragment("? ILIKE ?", ...)` is needed. The legacy code uses
`ilike(user.name, ^"%#{sanitized}%")` — replicate the same SQL-injection-safe
escaping.

Add code interface in `core.ex`:

```elixir
define :list_users, action: :list
```

### E6 — Add `remember_me` strategy to User

File: `lib/firmowid/ash/core/user.ex`

Inside the `authentication` block's `strategies` section:

```elixir
remember_me :remember_me do
  token_lifetime {30, :days}
end
```

On the `:sign_in_with_password` action, add:

```elixir
argument :remember_me, :boolean, allow_nil?: true

prepare {AshAuthentication.Strategy.RememberMe.MaybeGenerateTokenPreparation,
         strategy_name: :remember_me}

metadata :remember_me, :map, allow_nil?: true
```

**Open question:** The `:sign_in_with_password` action is auto-generated by
ash_authentication's password strategy. Verify whether defining it explicitly in
the `actions` block to add the remember_me argument/preparation works, or if it
requires a different approach (e.g., `sign_in_preparation` DSL option).
